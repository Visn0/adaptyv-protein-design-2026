# Structure explorers

One HTML file per promising design. Open the file in any browser — drag to
rotate, scroll to zoom. No server, no install.

- `e1b-d7x-t3-3-v6_explorer.html` — the project record (D47A; best ipSAE 0.871)
- `d7x-t3-3_explorer.html` — the parent champion (64 aa)
- `b2x-d12-2_explorer.html` — the independent scaffold (92 aa)

Keep `molstar-bundle.js` in the same folder as the HTML files.

## What this replicates

proteinbase's challenge explorer runs Mol* (the PDBe/RCSB viewer) with a
compact custom UI. These files reverse-engineer that setup: the same engine
(their bundle), the same buttons, icons and modes.

- **Cartoon / Surface** — switch representation. Target chains use
  proteinbase's cyan family (#0099ff / #00d2ff / #03ffff); the binder is pink.
- **CHAINS** — show or hide individual chains.
- **Coloring options** — pLDDT (confidence; blue = high), Hydrophobicity,
  Interface (interface residues as amber ball+stick).
- **Reset zoom / Screenshot / Selection mode / Fullscreen** — as on their site.

Structure: the Boltz-2 fold of the complex. The B-factor column carries the
pLDDT score, so the confidence colouring is the real prediction confidence.

## Viewpoint renders (`views/`)

`views/<name>/` holds three viewpoints per view mode (cartoon, surface, pLDDT,
hydrophobicity, interface) plus `manifest.json` — rendered headless by
`tools/report/molstar_views.py`, the agent-facing tool. It takes any complex:

```bash
.venv/bin/python tools/report/molstar_views.py --complex fold.cif \
    --name mydesign --out outdir --explorer
```

Inputs: one complex file (PDB or mmCIF), or `--binder FILE --target FILE`.
The interface residues are computed from the structure (4.5 A heavy-atom
contact, both sides). `--explorer` also writes the interactive page.

## Provenance

- Engine and icons: the Mol* bundle (MIT) and the cartoon/surface SVG icons
  were fetched from proteinbase's public site.
- Explorers are generated by `scripts/make_molstar_explorer.py` (project venv,
  repo root):

```bash
.venv/bin/python challenges/02-tnfa/viewers/scripts/make_molstar_explorer.py d7x-t3-3 b2x-d12-2 e1b-d7x-t3-3-v6
```

The generator reads the fold CIFs, the MD interface contacts and its icon
assets from the working directory `~/c2-work/md-anim/` (paths at the top of
the script). Designs without an MD run get their interface computed from the
fold itself.

Honesty: a fold is a model, not a binding measurement.
